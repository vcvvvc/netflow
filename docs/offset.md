# 网络报文中的 `offset`（偏移）

## 1. 偏移是什么

偏移表示某个字段距离报文起始位置的字节数。`data[0]` 是第一个字节，数组下标从 `0` 开始。

需要区分两种偏移：

- 相对偏移：字段距离当前协议头起点的位置。
- 绝对偏移：字段距离整个报文起点的位置。

## 2. 先看整个报文

在普通 Ethernet II 报文中，Ethernet 头占 `14` 字节，因此 IPv4 头从 `data[14]` 开始。

“偏移”就是：从报文第一个字节开始数，现在要看的字段距离开头多少个字节。

把报文想成一排编号：

```text
data[0]   data[1]   data[2]   ...   data[13]   data[14] ...
|--------- Ethernet 头，共 14 字节 ---------|
                                             |
                                             IPv4 头开始
```

## 3. 再看 IPv4 头内部

IPv4 头内部又从 `0` 开始编号：

```text
IPv4 头内部偏移：

0       1       2       ...   12  13  14  15  16  17  18  19
|版本等|       其他字段       |------源 IP------|------目的 IP------|
```

这里的数字是“相对于 IPv4 头起点”的偏移，不是相对于整个报文的绝对位置。

因此，无 VLAN 时：

```text
源 IP：    data[14 + 12] = data[26] ~ data[29]
目的 IP：  data[14 + 16] = data[30] ~ data[33]
```

| 字段 | IPv4 头内相对偏移 | 报文绝对位置 |
| --- | ---: | ---: |
| 源 IP | `12` 到 `15` | `data[26]` 到 `data[29]` |
| 目的 IP | `16` 到 `19` | `data[30]` 到 `data[33]` |

## 4. 为什么数组下标容易出错

源 IP 起点是 `data[26]`，四个字节依次是：

```text
第 1 个字节：data[26]，相对偏移 0
第 2 个字节：data[27]，相对偏移 1
第 3 个字节：data[28]，相对偏移 2
第 4 个字节：data[29]，相对偏移 3
```

所以，`14 + 12 + 3 = 29` 表示源 IP 的第 4 个字节，因为数组下标从 `0` 开始。

## 5. IPv4 头长度与 UDP 位置

IPv4 的 `IHL` 单位是 32 位字，也就是 4 字节：

```text
IPv4 头长度 = IHL × 4
UDP 起点 = Ethernet 头长度 + IHL × 4
```

例如：

```text
IHL = 5  → IPv4 头长度 20 字节 → UDP 从 data[34] 开始
IHL = 6  → IPv4 头长度 24 字节 → UDP 从 data[38] 开始
```

IPv4 options 会改变 UDP 起点，但不改变源 IP 和目的 IP 在 IPv4 头内的相对位置。

本文的绝对偏移推导假设链路层是普通 Ethernet II，暂不考虑 VLAN 等额外链路层头部。

## 6. 为什么 `FlowKey` 中使用 `uint32_t`

IPv4 地址本质上是 4 个字节，使用 `uint32_t` 可以：

- 用固定 4 字节保存；
- 方便比较和哈希；
- 适合放入流键 `FlowKey`；
- 只在打印时转换成 `A.B.C.D` 字符串。

保存时必须统一字节序。当前推导采用网络字节序对应的高位到低位排列。
